# V65 — Profile fixes

## บั๊กที่แก้

### 1. เนื้อหาหายบนการ์ด "Production Collaboration"
`<strong>` ที่ครอบคำว่า "End-to-end" มี `data-i18n-en`/`data-i18n-th` ติดอยู่ ทำให้สคริปต์สลับภาษาที่ทำงานตอนโหลดหน้าเขียนทับเนื้อหาข้างในทั้งหมด รวมถึง `<small>production management</small>` ที่ซ้อนอยู่ ทำให้ข้อความส่วนนั้นหายไปทั้ง Desktop และ Mobile

แก้โดยย้าย `data-i18n-en`/`data-i18n-th` ไปไว้ที่ `<span>` ใหม่ที่ครอบเฉพาะคำว่า "End-to-end" แทน ปล่อยให้ `<small>` ที่ซ้อนอยู่ทำงานอิสระ

ตรวจสอบทั้งเว็บแล้ว นี่เป็นจุดเดียวที่มีปัญหารูปแบบนี้

### 2. ช่องว่างผิดปกติบนมือถือใน "Management approach"
ตัวเลข 01–04 มี `margin-bottom: auto` ที่ดันเนื้อหาลงล่างการ์ด ซึ่งตั้งใจไว้สำหรับ Desktop (4 คอลัมน์ สูงเท่ากัน) แต่ไม่ได้ปิดไว้ตอนจอแคบ ทำให้เกิดช่องว่างมากผิดปกติระหว่างตัวเลขกับหัวข้อ

แก้โดยปิด `margin-bottom:auto` และเอา `min-height` คงที่ออกที่ breakpoint 900px ให้การ์ดสูงตามเนื้อหาแทน เหมือนที่ Capability map ทำอยู่แล้ว

## การเปลี่ยนแปลงอื่นตามที่ขอ

### รูปโปรไฟล์ → กรอบว่าง
เอารูปถ่ายออกจาก `.profile-portrait-frame` ชั่วคราว แทนที่ด้วยไอคอนรูปคนแบบเส้น (`icon-portrait-placeholder.svg`) และข้อความ "Photo coming soon" / "รูปถ่ายกำลังจะมาเร็วๆ นี้" กรอบเดิม (เส้นตาราง จุดตกแต่ง มุมโค้ง) ยังอยู่ครบ เหลือแค่แทนที่ path รูปใน `profile.html` เมื่อมีรูปใหม่

### Animation
เดิมทุก Section เล่น Fade-in พร้อมกันตอนโหลดหน้าเดียว (ไม่ค่อยน่าสนใจ และช้าถ้าเนื้อหายาว) เปลี่ยนเป็นใช้ระบบ Scroll-reveal เดียวกับหน้าอื่นในเว็บ (`.reveal-item` + IntersectionObserver ใน `motion.js`) — แต่ละ Section ทยอยปรากฏตอนเลื่อนเข้ามาในจอแทน ส่วน Hero (From making forms./To building brands.) ยังคง Fade-in ทันทีตอนโหลดหน้าเหมือนเดิมเพราะเป็นจุดแรกที่เห็น

หมายเหตุ: `motion.js` เป็นไฟล์ร่วมของทั้งเว็บ การเพิ่มนี้จึงกระทบเฉพาะหน้าที่มี class `.profile-*` เท่านั้น หน้าอื่นไม่มี Element เหล่านี้อยู่แล้วจึงไม่ได้รับผลกระทบ ได้ปรับ Cache-busting query (`?v=650`) ของ `motion.js` ในทุกหน้าที่เรียกใช้ เพื่อให้เบราว์เซอร์โหลดไฟล์ใหม่แทนไฟล์แคชเก่า

## วิธีตรวจสอบ (สำหรับอ้างอิง)
ใช้ Headless Chrome (Playwright) render หน้าเว็บจริงและตรวจ Computed Style / Screenshot จริง แทนการอ่านโค้ดเดาอย่างเดียว ระหว่างตรวจพบสิ่งที่ดูเหมือนบั๊กแต่พิสูจน์แล้วว่าไม่ใช่ (เป็นผลข้างเคียงจากวิธี Capture แบบ Full-page ที่ไปชนกับ Element ที่ตั้งใจซ่อนด้วย `position:fixed` เช่น Skip-link และ Page-transition overlay) จึงไม่ได้แก้สิ่งเหล่านั้นเพราะไม่ใช่ปัญหาจริงที่ผู้ใช้จะเห็น
