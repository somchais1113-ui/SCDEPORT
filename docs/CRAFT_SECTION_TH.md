# Craft & Process — โครงสร้างและวิธีแก้ไข

## หน้าที่เพิ่มเข้ามา

| ไฟล์ | หน้าที่ |
| --- | --- |
| `craft.html` | หน้ารวม 5 เทคนิค (Offset / Gravure / Flexo / Silkscreen / Engraving) |
| `craft-detail.html?id=<slug>` | หน้ารายละเอียดต่อเทคนิค พร้อมตัวอย่างงาน 4 ชิ้น |
| `data/craft.js` | ไฟล์ข้อมูลเดียวที่แก้เนื้อหาทั้งหมด |
| `assets/js/craft.js` | ตัวเรนเดอร์ ใช้ร่วมกันทั้งสองหน้า |
| `assets/css/craft.css` | สไตล์เฉพาะเซกชันนี้ |

slug ที่ใช้ได้: `offset`, `gravure`, `flexo`, `silkscreen`, `engraving`

## จุดเชื่อมเข้าเว็บเดิม

- `index.html` เพิ่มลิงก์รอง "Craft & Process" ใต้ปุ่ม Enter portfolio
- `home.html` เพิ่มเมนู "Craft & Process" ใน nav และเพิ่มเซกชันแนะนำก่อน Object Study

## ภาพประกอบ

ไฟล์ทั้งหมดอยู่ที่ `assets/images/craft/<slug>/` เป็น WebP ขนาด **1400 x 1050 (4:3)**
ระบุขนาดไว้ในชื่อไฟล์ตามธรรมเนียมเดิมของโปรเจกต์

```
assets/images/craft/offset/
├── cover-1400x1050.webp        ภาพบนหน้ารวม
├── example-01-1400x1050.webp   ตัวอย่างที่ 1
├── example-02-1400x1050.webp   ตัวอย่างที่ 2
├── example-03-1400x1050.webp   ตัวอย่างที่ 3
├── example-04-1400x1050.webp   ตัวอย่างที่ 4
└── UPLOAD-NAMES.txt            คำอธิบายว่าแต่ละช่องควรใส่ภาพอะไร
```

> **ภาพชุดนี้เป็น Placeholder ทั้งหมด** ไม่ใช่ภาพงานจริง
> ต้องเขียนทับด้วยภาพถ่ายของคุณเอง โดยคงชื่อไฟล์และขนาดพิกเซลเดิมไว้
> ถ้าเปลี่ยนสัดส่วนจาก 4:3 เลย์เอาต์จะขยับ

เลือกสัดส่วน 4:3 เพราะตรงกับกล่องภาพในระบบเดิม จึงไม่เกิดแถบขาว letterbox
และไม่เกิดปัญหา "เส้นลอย" แบบที่แก้ไปใน v45

## วิธีแก้เนื้อหา

แก้ที่ `data/craft.js` ไฟล์เดียว ไม่ต้องแตะ HTML

- `spec` คือพารามิเตอร์ 4 ช่อง (Mechanism / Resolution / Substrate / Run sweet spot)
- ทุกฟิลด์มีคู่ภาษาไทย ลงท้ายด้วย `Th` เช่น `quote` กับ `quoteTh`
- `examples` คือตัวอย่างงาน 4 ชิ้น ปรับ `caption` และ `alt` ให้ตรงกับภาพจริง

## ก่อนเผยแพร่จริง

1. **ตรวจตัวเลขทุกตัวใน `spec`** ตอนนี้เป็นค่าอ้างอิงทั่วไปของอุตสาหกรรม
   ไม่ใช่ข้อมูลที่ยืนยันจากประสบการณ์จริง โดยเฉพาะ LPI และจุดคุ้มทุน Run
2. เปลี่ยนภาพ placeholder เป็นภาพงานจริงให้ครบ 25 ไฟล์
3. เมื่อตรวจครบแล้ว เปลี่ยน `draft: true` เป็น `draft: false` ในแต่ละรายการ
   กล่องเตือนสีจางบนหน้ารายละเอียดจะหายไปเอง

## แก้ไข v3 — ตัวอักษรทับกัน และการจัดฟอนต์

### สาเหตุที่ตัวอักษรทับกัน

ไม่ใช่ปัญหา line-height หรือ margin แต่เป็นเรื่อง CSS selector ชนกัน

`main.css` มีกฎนี้อยู่

```css
.eyebrow span {
  width: 6px;
  height: 6px;
  border-radius: 50%;
  background: var(--accent);
}
```

กฎนี้จับ **ทุก span** ที่อยู่ใน `.eyebrow` เพื่อทำเป็นจุดกลมเล็ก ๆ นำหน้าข้อความ
เว็บเดิมจึงต้องใส่ class `eyebrow-copy` ให้ span ที่เป็นข้อความเสมอ
แล้ว `ui-controls.css` จะรีเซ็ตกลับเป็น auto

```css
.eyebrow .eyebrow-copy {
  width: auto;
  height: auto;
  flex: 0 1 auto;
  background: none;
}
```

โค้ดที่ผมเขียนตอนแรกสร้าง span เปล่าโดยไม่ใส่ class นี้
ข้อความจึงถูกบีบให้กว้าง 6px สูง 6px แล้วล้นทะลุออกไปทับบรรทัดถัดไป

**แก้แล้ว** โดยเพิ่มฟังก์ชัน `eyebrow()` ใน `assets/js/craft.js`
ที่ใส่ `class="eyebrow-copy"` ให้อัตโนมัติทุกจุด
ตรวจแล้วความกว้างกลับมาเป็น 185-209px ตามปกติ

### ฟอนต์ที่ใช้ อ้างอิงจากระบบเดิมทั้งหมด

| บทบาท | ฟอนต์ | อ้างอิงจากส่วนไหนของเว็บเดิม |
| --- | --- | --- |
| เนื้อหาและ UI (EN) | `SC Google Sans` | กำหนดที่ `body` ใน `ui-controls.css` |
| เนื้อหาและ UI (TH) | `SC Prompt` | สลับด้วย `[data-language="th"]` |
| ประโยคเน้น (quote) | Georgia italic | บทบาทเดียวกับ `.hero h1 em` และ `.intro-strip p` |
| ป้ายกำกับเล็ก | 10px / uppercase / 0.1em | ค่าเดียวกับ `.case-information small` |

ไม่ได้เพิ่มฟอนต์ใหม่เข้ามาเลย

### จุดที่ปรับเพิ่มสำหรับภาษาไทย

ภาษาไทยไม่มี serif italic ที่เข้าคู่กับ Georgia จึงทำแบบเดียวกับที่เว็บเดิม
ทำกับ `.intro-strip p` คือสลับเป็น `SC Prompt` ตัวตรง และลด letter-spacing
ของ eyebrow ให้เหลือ 0.025em ตามหน้า home

### ผลตรวจอัตโนมัติ

ตรวจการทับซ้อนของกล่องข้อความทุกคู่ใน 5 กรณี
(desktop EN, mobile EN, mobile TH, detail desktop EN, detail mobile TH)
ผลคือ **ไม่พบการทับซ้อน** และไม่มี JavaScript error

## แก้ไข v4 — ระยะขอบและ alignment

ภาพที่ส่งมารอบนี้เป็นไฟล์เดิมจากรอบก่อน (ยังเห็น LITHO ทับ MECHANISM อยู่)
เช็คแล้วบั๊กนั้นแก้ไปแล้วใน v3 — ถ้าเปิดจากไฟล์ zip รอบนี้ (v4) จะไม่เห็นปัญหานั้นแล้ว
ถ้าเทสต์ผ่าน URL ที่เคยเปิดค้างไว้ ลอง hard refresh หรือ deploy ไฟล์ชุดใหม่ทับก่อน

ส่วนเรื่องระยะขอบที่แจ้งมา ตรวจแล้วพบว่าจริง — หน้า Craft & Process ใช้ระยะขอบ
เดียวกับทั้งเว็บ (`.shell` ใน `main.css` = `clamp(24px, 3.2vw, 56px)`)
ซึ่งพอดีกับหน้าอื่นที่เนื้อหาเป็นภาพเต็มกรอบ แต่พอเป็นตัวหนังสือล้วนวางชิดขอบจอ
โดยเฉพาะตอนอยู่บนมือถือที่รูปกับข้อความเรียงต่อกันเป็นคอลัมน์เดียว จะรู้สึกอึดอัดกว่า

**แก้โดยเพิ่มค่าเฉพาะหน้านี้** ไม่แตะ `.shell` ส่วนกลาง (เพราะกระทบทุกหน้าในเว็บ)

```css
.craft-page .shell {
  padding-inline: clamp(28px, 6vw, 56px);
}
```

ระยะขอบมือถือขยับจาก 24px เป็น 28px และปรับ `.craft-row__content` ให้ gap
ระหว่างบรรทัดมากขึ้นเป็น 18px (จากเดิม 15px) เมื่ออยู่บนคอลัมน์เดียว
เพื่อให้เนื้อหาแต่ละส่วนหายใจง่ายขึ้น ตรวจด้วยสคริปต์แล้วว่าองค์ประกอบทุกชิ้น
(eyebrow, quote, spec, close) เริ่มที่ตำแหน่ง left เดียวกันทั้งหมด (28px จากขอบจอที่ 390px)
